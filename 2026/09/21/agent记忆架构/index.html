agent记忆架构

2026-09-21

1. 记忆架构总览：

  • 短期记忆：短期记忆一般保留近期完整聊天消息。

  • 长期记忆：长期记忆保留一些之前的需要持久化的消息：

    类型 例子 存储方式
    用户事实/偏好 “用户用 Python”、”时区 UTC+8” 结构化字段，会话开始直接加载
    情景记忆 “上周帮用户排查过 XX bug，结论是 XX” 向量库，按需检索
    程序性记忆 学到的可复用工作流 类似 Voyager 的 skill 库
    会话摘要 每次会话一段总结 向量库

2. 短期记忆实现:

  • 保留原则：
    • 一般保留完整对话，用户一问，AI一答，属于一个完整的轮次。
    • 不能切在 tool_call 和 tool_result 之间
    • 建议按 token 数而不是固定轮数裁剪——工具结果（比如读了个大文件）长度差异巨大
    • 超窗的旧轮次不要直接丢，压缩成摘要放前面；过长的单个工具结果可以只保留首尾截断

3. 长期记忆实现：

触发时机有两种： 1. 事件触发 2.阈值触发

  • 事件触发：通过漏斗式进行长期记忆存储：
    • L0层：
      • 显式信号：记住、以后都、我是、我们公司用
      • 纠正信号：不对、不是、我说的是 —— 价值最高，必触发
      • 限流：每会话最多抽取 K 次，两次之间至少隔 N 轮
      • 纯工具结果轮、“好的/继续”这类短轮次直接跳过（可选）
    • L1层：
      • 利用小模型去判断当前会话中是否有可沉淀的长久记忆，判断的位置可以在消息结构中维护游标，来表示下一次从第几轮判断。
    • L2层：
      • 抽取候选记忆
        → 每条候选去向量库搜相似既有记忆
        → LLM 判断操作：
        NOOP （重复，跳过）
        UPDATE （合并，新信息覆盖旧的）
        DELETE （直接矛盾，删除旧的）
        ADD （全新，插入）
  • 阈值触发：在压缩上下文的时候，顺便调用模型执行L1层和L2层。

note: 说实话，如果你的产品会话普遍很短（<30 分钟），只做会话结束批量抽取就完全够了

4.长期记忆膨胀

写入本身便宜，可怕的是低价值记忆堆积拖垮检索精度。防线：

  • 写入时打 importance 分
  • 会话级写入预算：单会话最多落 N 条
  • 定期整理任务：合并相似、归档「低 importance + 低 use_count + 老」的记忆
